1. Arsitektur Proyek & Mental Model (Next.js vs Laravel)

Pada praktikum Pertemuan 2, fokus utama dititikberatkan pada penguasaan JavaScript modern (ES6+), operasi array murni (immutable), dan pemisahan tugas secara modular. Perbandingan arsitektur yang diterapkan meliputi:

  • Konvensi Folder data/: Khusus menyimpan data mentah statis (seperti data/barang.json) tanpa komputasi.
  • Konvensi Folder lib/: Berisi pustaka logika, helper format (formatRupiah, formatTanggal), dan pustaka murni komputasi (lib/hitung.js).
  • Immutability: Menjaga integritas data asli dengan menghindari mutasi langsung seperti .push() atau .sort(), melainkan memanfaatkan spread operator [...array] dan method bawaan non-mutasi (.map(), .filter(), .reduce()).

A. Pustaka Fungsi Modular (lib/hitung.js)

Seluruh logika perhitungan didefinisikan ke dalam 14 fungsi murni (pure functions) yang diekspor secara modular: 

import { BOBOT } from "./nilai.js";

// Nilai Akhir Berbobot (Tugas 30%, UTS 30%, UAS 40%) dibulatkan 2 desimal
export const nilaiAkhir = ({ tugas, uts, uas }, bobot = BOBOT) =>
  Math.round((tugas * bobot.tugas + uts * bobot.uts + uas * bobot.uas) * 100) / 100;

// Penentuan Huruf Mutu
export function hurufMutu(angka) {
  if (angka >= 85) return "A";
  if (angka >= 75) return "B";
  if (angka >= 65) return "C";
  if (angka >= 50) return "D";
  return "E";
}

// Menentukan Kelulusan (Standar >= 65)
export const lulus = (angka, batas = 65) => angka >= batas;

// Pengurutan Array secara Immutable
export const urutkan = (daftar, kolom, arah = "turun") =>
  [...daftar].sort((a, b) => (arah === "naik" ? a[kolom] - b[kolom] : b[kolom] - a[kolom]));

// Peringkat N Teratas
export const peringkat = (daftar, n = 3) => urutkan(daftar, "akhir").slice(0, n);

4. Refleksi & Kesimpulan

Melalui rangkaian praktikum ini, implementasi komputasi nilai mahasiswa berhasil dipisahkan secara bersih antara lapisan data (lib/nilai.js), lapisan logika bisnis (lib/hitung.js), dan lapisan antarmuka pengguna (app/mahasiswa/page.js). Penggunaan Next.js 16 dengan Partial Prerendering (PPR) dan Suspense boundary memastikan aplikasi tetap cepat, teroptimasi secara statis, namun tetap adaptif terhadap query parameter penyaringan prodi.
